# SOUL READER 개인 개발자 등록 자료

개인 명의 Google Play 개발자 계정 기준의 **등록 초안**입니다. 계정·앱·상품을 아직 등록하거나 제출한 상태는 아니며, 현재 8.5.6 앱에서는 실제 구매가 비활성화되어 있습니다.

## 1. 계정 소유자가 먼저 진행할 일

1. 본인 Google 계정으로 [Play Console 가입](https://play.google.com/console/signup)을 엽니다.
2. 계정 유형을 **개인**으로 선택하고, Google이 요구하는 개발자·연락처 정보를 입력합니다.
3. 화면에 표시되는 등록비 납부와 본인·연락처·기기 확인 등 해당 계정의 필수 절차를 완료합니다.
4. 유료 인앱 상품 판매를 위한 결제 프로필·정산 정보와 필요한 인증을 본인 정보로 설정합니다.

현재 작업 환경에는 본인 Play Console에 로그인하여 조작할 수 있는 연결이 없습니다. 계정 생성·본인 인증·등록비 납부·정산 정보 입력은 소유자가 Google 화면에서 진행해야 합니다. 비밀번호, 인증번호, 신분증, 카드·계좌 정보는 채팅이나 저장소에 올리지 않습니다.

개인 계정에 적용되는 출시 전 테스트와 기기 확인 요건은 Console의 해당 계정 안내로 확인합니다. **내부 테스트 업로드와 정식 출시 승인은 별개**입니다.

## 2. 앱 생성 시 입력할 초안

| 항목 | 입력안 | 상태 |
| --- | --- | --- |
| 앱 이름 | SOUL READER | 기존 앱 이름 |
| 기본 언어 | 한국어 | 제안 |
| 앱/게임 | 앱 | 제안 |
| 다운로드 가격 | 무료 | 인앱 구매 별도 |
| 카테고리 | 엔터테인먼트 | 제안 |
| Android 패키지명 | `com.soulreader.soul_reader` | 현재 생성값, 첫 AAB 업로드 전 최종 확인 필요 |
| 공개 개발자 이름 | 소유자가 결정 | 미정 |
| 고객지원 이메일 | 소유자가 제공 | 미정 |
| 개인정보처리방침 URL | 공개 웹페이지 주소 필요 | 미정 |

패키지명은 첫 업로드 전에 확정합니다. 위 값의 Play 등록 가능 여부는 아직 확인하지 않았습니다. 변경 시 Android 생성 스크립트·앱 설정·검증 서버의 패키지명도 함께 맞춰야 합니다.

**간단한 설명 초안**

> 류와 함께 즐기는 관상 이야기. 무료 풀이와 네 가지 주제별 콘텐츠를 만나보세요.

**자세한 설명 초안**

> SOUL READER는 관상 모티브의 창작 해설을 즐기는 엔터테인먼트 앱입니다.
>
> 사진 촬영·갤러리 선택과 기기 내 얼굴 윤곽 측정 기능을 제공합니다. 무료 콘텐츠를 살펴본 뒤 사랑·기회·일·인연의 주제별 콘텐츠를 선택할 수 있습니다. 류의 음성과 함께 이야기를 즐겨보세요.
>
> 유료 이용권은 구매한 사진의 풀이 한 건에 적용됩니다. 한 주제 이용권은 네 가지 중 한 주제를 확정해 이용하고, 합본 이용권은 네 주제를 모두 이용합니다. 다른 사진의 풀이는 별도 구매가 필요합니다.
>
> 풀이 문장은 오락용 창작 콘텐츠이며 과학적인 평가나 미래 예측을 제공하지 않습니다.

설명은 등록용 초안입니다. 최종 출시 기능과 일치하는지 확인한 뒤 사용합니다. 스크린샷·아이콘·그래픽과 콘텐츠 등급 설문도 별도 준비해야 합니다.

## 3. 일회성 인앱 상품 두 개

| 항목 | 한 주제 | 네 주제 합본 |
| --- | --- | --- |
| 제안 상품 ID | `soul_reading_single` | `soul_reading_bundle` |
| 상품 이름 | 한 사진 · 한 주제 이용권 | 한 사진 · 네 주제 합본 |
| 한국 판매 가격 | ₩990 | ₩1,990 |
| 제공 범위 | 구매한 풀이 한 건의 네 주제 중 하나 | 구매한 풀이 한 건의 네 주제 모두 |

**한 주제 상품 설명**

> 구매한 사진의 풀이 한 건에서 사랑·기회·일·인연 중 한 주제를 이용합니다. 주제 확정 후 변경할 수 없으며, 다른 사진에는 적용되지 않습니다.

**합본 상품 설명**

> 구매한 사진의 풀이 한 건에서 사랑·기회·일·인연 네 주제를 모두 이용합니다. 다른 사진에는 적용되지 않습니다.

상품 ID는 아직 등록 전 제안값입니다. Console에서 실제 ID·판매 지역·가격·활성 상태를 설정하고 앱·서버에 동일하게 연결합니다. 앱은 Play가 반환하는 실제 가격을 표시합니다. 소비형 처리는 앱의 구매 후 소비 처리로 구현하며, 다중 수량 판매는 사용하지 않습니다.

## 4. 실제 결제까지 남은 작업

1. 개인 개발자 계정·앱·두 상품을 등록합니다.
2. 로그인 방식을 확정하고 앱의 인증 세션을 구현합니다. 로그인 방식은 아직 확정되지 않았습니다.
3. 구매 검증 서버·영구 거래 원장·환불 반영을 구현하고 Google Play 권한을 연결합니다.
4. 업로드 서명과 Play App Signing을 설정하고, 실제 상품 ID·HTTPS 서버 주소를 넣은 출시용 AAB를 빌드합니다.
5. 내부 테스트와 라이선스 테스트에서 구매·취소·대기·재시도·복원·주제 확정을 검증합니다. 정식 출시에는 Console이 요구하는 추가 절차를 완료합니다.

구매 권한 복원에는 서버 원장과 사용자 식별이 필요합니다. 현재 클라이언트의 복원 대상은 기기에 남은 풀이 기록이며, 삭제한 사진·풀이를 재설치나 다른 기기에서 복구하는 동기화 기능은 구현되지 않았습니다.

개인정보처리방침과 데이터 보안 설문은 최종 로그인·서버·SDK 동작을 확인한 뒤 작성합니다. 얼굴 윤곽 측정이 기기 내에서 이뤄진다는 이유만으로 앱 전체를 ‘데이터 수집 없음’으로 신고하지 않습니다.
