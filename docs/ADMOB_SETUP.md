## 1. 앱에 들어가는 광고

- 형식: **일반 전면 광고(Interstitial)** 한 개입니다. 보상형 광고나 보상형 전면 광고가 아닙니다.
- 시점: 새 사진의 무료 기본 풀이 결과를 처음 열기 직전에 최대 한 번 요청합니다. 무료 여섯 항목을 각각 열 때마다 광고를 요청하지 않습니다.
- 저장된 풀이 다시 열기, 유료 풀이, 심사용 검토 접근에는 이 광고를 요청하지 않습니다.
- 광고나 동의 정보를 불러오지 못하거나 표시할 광고가 없으면 무료 풀이를 계속 보여줍니다. 광고가 이미 표시되었다면 닫기 또는 SDK의 표시 실패 처리가 끝난 뒤 풀이로 돌아옵니다.
- 광고 요청에는 사진·얼굴 특징·풀이 본문·풀이 ID·로그인 UID·이메일·구매 토큰을 넣지 않습니다. SDK 자체의 앱·기기·광고 정보 처리는 별도로 있습니다.

## 2. 먼저 v99에서 테스트 광고 확인

계정이 없어도 `test` 모드 AAB로 동작을 확인할 수 있습니다. Google에서 제공하는 Android 테스트 ID를 사용합니다.

| 용도 | Google 테스트 ID |
| --- | --- |
| Android 앱 ID | `ca-app-pub-3940256099942544~3347511713` |
| 전면 광고 단위 ID | `ca-app-pub-3940256099942544/1033173712` |

GitHub Actions의 **Build SOUL READER Android → Run workflow**에서 `artifact_type=internal_aab`, `version_code=99`, `ads_mode=test`를 사용합니다. v99가 이미 업로드되었다면 이후 AAB에는 더 큰 버전 코드를 사용합니다. 원래 업로드 키를 유지하며 `TEST_ADS` 표시가 있는 결과물을 확인합니다. 빌드 성공과 Play 설치 후 실기기 확인은 별도입니다.

- [ ] Play 내부 테스트로 설치한 앱에서 테스트 광고 표시를 확인합니다. 실제 광고 ID로 자신의 광고를 누르지 않습니다.
- [ ] 새 무료 풀이 한 번 → 전면 광고 닫기 → 여섯 항목 풀이가 열리는지 확인합니다.
- [ ] 저장된 풀이 다시 열기·유료 풀이·검토용 접근에 이 광고가 나타나지 않는지 확인합니다.
- [ ] 네트워크 해제·광고 없음·동의 정보 오류 때 무료 풀이가 계속 열리는지 확인합니다.
- [ ] 광고/동의 화면 중 앱을 백그라운드로 보냈다가 복귀하고, 연속 누르기에도 광고와 결과가 중복되지 않는지 확인합니다.
- [ ] 광고를 포함한 테스트 버전도 Play Console의 **광고 포함** 및 **데이터 보안** 응답을 실제 빌드에 맞게 검토합니다. 테스트라는 이유로 기존 v98 응답이 자동으로 맞는 것은 아닙니다.

## 3. 소유자 AdMob 계정과 Android 앱 만들기

1. 소유자의 Google 계정으로 [Google AdMob](https://admob.google.com/)에 가입합니다. 국가·시간대·결제 프로필 등은 소유자가 사실에 맞게 직접 설정합니다. 계정 승인·정산·세금·본인 확인은 AdMob 안내를 따릅니다.
2. **앱 → 앱 추가 → Android**를 선택합니다. SOUL READER가 아직 공개 스토어에 없으면 **지원되는 앱 스토어에 등록되어 있나요? → 아니요**로 추가합니다. 이미 공개되어 있다면 정확한 Google Play 앱을 연결합니다.
3. 앱 이름을 SOUL READER로 지정하고 패키지 `com.soulreader.soul_reader`를 대조합니다. 비공개 앱 추가만으로 앱 준비 상태 검토와 실제 광고 게재 승인이 완료되지는 않습니다.
4. **앱 설정**에서 Android **앱 ID**를 복사합니다. 모양은 `ca-app-pub-16자리~10자리`입니다.
5. **광고 단위 → 광고 단위 추가 → 전면 광고**를 선택합니다. 예를 들어 `new_free_reading`이라는 이름으로 만들고 **광고 단위 ID**를 복사합니다. 모양은 `ca-app-pub-16자리/10자리`입니다. 일반 전면 광고가 맞는지 확인합니다.
6. **계정 설정 → 계정 정보**에서 **게시자 ID**(`pub-16자리`)를 확인합니다. 이 값은 아래 `app-ads.txt`용이며 앱 ID/광고 단위 ID와 구분합니다.

앱 ID·광고 단위 ID·게시자 ID는 앱과 공개 `app-ads.txt`에 사용되는 **공개 식별자**입니다. Google 비밀번호, AdMob 로그인, 은행 계좌, 세금·신분증 정보, API 키, 서비스 계정 키는 필요하지 않으며 채팅·GitHub·공개 문서에 공유하지 않습니다.

## 4. 공개 스토어 연결과 app-ads.txt 확인

실제 수익화 전에는 AdMob 화면의 **앱 준비 상태 / 앱 인증 / 정책 센터**에서 필요한 조치를 완료해야 합니다. 새 앱에 요구되는 `app-ads.txt` 확인을 건너뛰지 않습니다. AAB를 내부 테스트에 업로드한 것만으로 공개 스토어 연결과 앱 승인이 끝나는 것은 아닙니다.

1. Google Play 스토어의 개발자 연락처 **웹사이트**에 소유자가 관리하는 공개 웹사이트를 등록합니다. 개인정보처리방침 칸과 별개입니다. 공개 주소는 `https://soul-reader-billing.jgw98541706.workers.dev/`이며, `/privacy`·`/delete-account`로 연결되는 서비스 안내를 제공합니다.
2. 서버 [wrangler.jsonc](../server/wrangler.jsonc)의 공개 변수 `ADMOB_PUBLISHER_ID`는 `pub-1953724823797056`으로 설정했습니다. 서버 배포 후 Cloudflare의 기존 `soul-reader-billing` Worker에서 같은 텍스트 변수가 적용되었는지 확인합니다. 비밀 값이 아니며 기존 인증·구매 키는 변경하지 않습니다.
3. 같은 웹사이트 호스트의 루트 `/app-ads.txt`를 로그인 없이 열어 AdMob이 제시한 행과 정확히 같은지 확인합니다.

   ```text
   google.com, pub-1953724823797056, DIRECT, f08c47fec0942fa0
   ```

   서버는 형식이 맞는 소유자 ID가 설정된 경우에만 행을 생성합니다. 미설정·형식 오류·Google 테스트 게시자·모든 자리가 0인 값이면 **404**입니다. 테스트용 가짜 판매자 파일은 만들지 않습니다. 형식 검사만으로 계정 소유권을 증명하지는 않습니다. 배포 후 공개 검사는 웹사이트·광고 조건부 개인정보 안내·계정 삭제 페이지와 위 판매자 행을 모두 확인합니다.
4. AdMob에 공개 Google Play 스토어 앱 링크를 연결합니다. AdMob 화면에서 인식한 개발자 웹사이트와 실제로 크롤링하는 `app-ads.txt` URL을 확인하고 **업데이트 확인/인증**을 진행합니다. 크롤링과 검토에는 시간이 걸릴 수 있습니다. `workers.dev` 호스트를 입력한 것만으로 도메인 인식과 인증 성공을 보장하지 않습니다. AdMob이 다른 호스트를 찾거나 해당 주소를 지원하지 않으면 소유자가 관리하는 도메인을 연결하고, 그 도메인의 루트에 같은 파일이 제공되도록 설정합니다.
5. `app-ads.txt` 인증, 앱 준비 상태의 광고 게재 승인, 계정/정책 제한 유무를 각각 확인합니다. 승인 전 실제 광고가 안 나오는 현상을 코드에서 강제로 우회하지 않습니다.

## 5. 동의와 개인정보 안내

AdMob **개인정보 보호 및 메시지(Privacy & messaging)**에서 출시 국가와 실제 운영에 필요한 동의 메시지를 설정·게시합니다. UMP는 정보를 갱신하고 필요한 동의 화면을 표시한 뒤 `canRequestAds`를 확인합니다. 필요한 지역에서는 앱의 광고 개인정보 선택 진입점으로 선택을 다시 열 수 있습니다. 메시지·지역 조건과 실제 기기에서의 동작을 확인해야 하며 SDK를 추가한 것만으로 동의 설정이 완료되지는 않습니다.

코드는 `nonPersonalizedAds: true`로 요청합니다. **비개인 맞춤 광고도 SDK의 IP·식별자·광고 측정/진단 처리를 없애지 않습니다.** 필요한 동의와 Play 신고를 생략하는 근거가 아닙니다. Google 테스트 ID에서는 소유자 앱에 게시한 UMP 메시지까지 검증되지 않을 수 있으므로, 소유자 앱을 연결한 뒤 Google이 안내하는 테스트 기기·동의 디버그 절차로 다시 확인합니다. 디버그 지역·테스트 기기 설정을 일반 사용자 출시 설정에 남기지 않습니다.

개인정보처리방침은 “광고 기능이 포함된 버전에서는”이라는 조건으로 광고 제공자·유형·처리 정보를 설명합니다. 기존 광고 없는 v98의 설명과 구분합니다. 새 정책의 코드 변경, 공개 서버 배포, 실제 공개 페이지 확인은 각각 완료 여부를 확인합니다.

데이터 보안은 [AdMob 추가 검토표](data-safety/ADMOB_ADDENDUM_KO.md)를 사용합니다. 기존 v98 일곱 유형 CSV를 광고 버전에 그대로 재사용하거나, SDK 데이터 공개 원문과 최종 설정 확인 없이 새 가져오기 파일을 제출하지 않습니다.

## 6. 실제 광고 ID로 빌드하고 수익화하기

실제 소유자의 앱 ID와 전면 광고 단위 ID가 준비되어 `live` 빌드를 만들 수 있습니다. **AdMob 앱 인증·게재 승인은 컴파일의 선행 조건이 아닙니다.** 계정·앱이 실제 광고를 송출할 수 있는지 확인하고 배포 시점에 다음 설정을 마무리합니다.

- [ ] 소유자 AdMob 계정·Android 앱·일반 전면 광고 단위가 준비됨
- [ ] 공개 스토어 앱 연결, AdMob 앱 인증/준비 상태 및 정책 센터 확인 완료
- [ ] 실제 소유자 게시자 ID로 `app-ads.txt` 공개·인증 완료
- [ ] UMP 메시지·개인정보 선택·출시 지역에 필요한 동의 흐름 검증 완료
- [ ] 개인정보처리방침 배포 및 Play의 광고 포함·데이터 보안 신고 갱신
- [ ] 테스트 광고로 새 풀이 한 번/다시 열기/유료/검토/오류 복귀 확인 완료

위 두 소유자 ID는 [공개 빌드 설정](../release/admob/public-config.json)에 저장합니다. `live` 모드에서는 환경 변수에 없는 ID를 이 파일에서 가져옵니다. 나중에 소유자 설정을 바꾸는 경우 GitHub 저장소 **Settings → Secrets and variables → Actions → Variables**의 `ADMOB_ANDROID_APP_ID`와 `ADMOB_INTERSTITIAL_AD_UNIT_ID`로 덮어쓸 수 있습니다. 두 값의 게시자 부분은 같은 소유자 계정이어야 합니다. 일부만 덮어써 게시자가 달라지거나 ID 형식이 틀리면 빌드를 중단하며, 실패 시 테스트 ID로 조용히 바뀌지 않습니다.

**Run workflow**에서 `artifact_type=internal_aab`, 기존 모든 업로드보다 큰 `version_code`(이번 대상은 `100`), `ads_mode=live`를 선택합니다. 수동 실행의 광고 기본값은 `test`입니다. `build/play-ads-live-v100` 푸시는 `live`·`100`, 기존 `build/play-ads-v99` 푸시는 `test`·`99`로 고정됩니다. 공개 ID 파일이나 변수를 저장하는 것만으로 광고 모드는 바뀌지 않습니다. `off`와 `test`는 소유자 ID 대신 Google 테스트 ID를 사용합니다. 라이브 모드에서 ID 누락·잘못된 형식·Google 샘플 ID는 빌드를 중단합니다.

`off`는 광고 요청을 끄는 빌드 모드입니다. SDK를 포함한 빌드를 과거의 SDK 없는 v98과 동일하다고 신고하지 않습니다. 최종 설치 AAB의 포함 SDK와 실제 초기화·통신 범위를 확인합니다.
