# v99 이후 광고 기능의 데이터 보안 추가 검토

2026-11-03 작성. 기존 [v98 검토표](REVIEW_KO.md)와 [일곱 유형 CSV](SOUL_READER_DATA_SAFETY_DRAFT.csv)는 광고 SDK 없는 v98 기준입니다. 이 추가 문서는 AdMob이 들어가는 빌드를 위한 검토 목록이며 **새 가져오기 CSV나 제출 완료 기록이 아닙니다.** 기존 CSV의 응답은 변경하지 않았습니다.

첫 v99는 Google 테스트 광고용입니다. 비개인 맞춤 광고 요청(`nonPersonalizedAds: true`), UMP 동의 사용, 테스트 광고 사용만으로 SDK의 데이터 처리가 없다고 신고할 수 없습니다. 앱 자체가 사진·얼굴 특징·풀이 본문·풀이 ID·로그인 UID·이메일·구매 토큰을 광고 요청에 보내지 않는다는 점과 SDK 자체 수집을 구분합니다.

## 새로 확인할 항목

최종 AAB의 `google_mobile_ads`와 포함된 Android Google Mobile Ads SDK·UMP 버전, 자동 수집, 동의 설정, 광고 요청 옵션을 공식 자료와 대조합니다. 공식 기준 문서는 [Google Mobile Ads Android 데이터 공개](https://developers.google.com/admob/android/privacy/play-data-disclosure)입니다. 이 작업 환경에서는 해당 공식 웹페이지 본문 접근이 차단되어 최신 원문을 직접 확인하지 못했습니다. 아래는 **공식 원문 및 최종 빌드 대조가 필요한 검토 항목**이며, 모든 행의 응답을 임의로 확정한 표가 아닙니다.

| SDK 처리 정보의 검토 항목 | Play 데이터 유형 후보 | v98와 비교한 검토 |
| --- | --- | --- |
| IP 주소 및 IP에서 추정한 대략적 위치 | 위치 → 대략적 위치 | **추가 검토 필수.** 위치 권한/GPS 기능이 없어도 IP 기반 위치가 해당할 수 있습니다. 기존 위치 미선택을 그대로 유지하지 않습니다. 정밀 위치와 구분합니다. |
| 광고 조회·탭, 앱 실행 등 사용자와 광고/제품의 상호작용 | 앱 활동 → 앱 상호작용 | 기존 선택된 유형이지만 수집/공유 주체와 광고 목적을 재검토합니다. |
| 앱/SDK 성능, 실행 시간, 멈춤·오류 등 진단 정보 | 앱 정보 및 성능 → 진단, 비정상 종료 로그 등 | 기존 진단 유형에 광고 SDK 처리를 합쳐 검토합니다. **비정상 종료 로그를 별도 선택할지**는 공식 공개 문서의 실제 데이터 항목과 Play 정의로 판단합니다. |
| 광고 ID, 앱/기기 및 그 밖의 SDK 식별자 | 기기 또는 기타 ID | 기존 선택된 유형이지만 자동 수집·공유·보안/광고 목적과 SDK 설정을 재검토합니다. 앱에서 UID를 넣지 않는다는 사실만으로 이 유형을 지우지 않습니다. |

정밀 위치·사진·동영상·연락처·결제 수단·건강·성적 지향 등 기존에 선택하지 않은 유형을 광고 추가만으로 전부 선택하지 않습니다. 실제 수집을 근거로 검토합니다. Google이 말하는 기기/계정 식별자와 앱에서 Firebase UID를 직접 광고 요청에 넣는 행위도 같은 것으로 단정하지 않습니다.

## 유형별 응답을 확정하는 기준

- **수집/공유:** SDK가 기기 밖으로 보내는 정보와 Google의 역할을 확인하고, 공식 SDK 안내 및 Play의 공유 예외 정의와 대조합니다. “비개인 맞춤”, “광고를 판매하지 않음”, “서비스 제공자 사용” 중 하나만으로 모든 공유를 아니요로 만들지 않습니다.
- **목적:** 공식 자료에서 광고 SDK가 밝힌 광고/마케팅·분석·사기 예방/보안 용도를 각 데이터 유형과 실제 설정에 맞게 확인합니다. 기존 세 SDK 유형의 “공유 목적: 분석”만 유지하면 광고 목적이 빠질 수 있습니다. 모든 유형에 모든 목적을 일괄 선택하지 않습니다.
- **필수/선택:** UMP 화면의 존재나 무료 풀이의 오류 시 계속 진행만으로 SDK 데이터 수집 전체가 선택적이라고 확정하지 않습니다. 동의 지역, 비개인 맞춤/제한 광고 처리, 동의 전 SDK 통신과 무료 기능 전체의 설정을 기준으로 판단합니다.
- **일시적 처리:** 광고 요청이 짧게 끝나는 것과 Google이 정보 전부를 메모리에서만 처리하고 즉시 삭제하는 것은 다릅니다. SDK 보관·사용 설명을 확인합니다.
- **전송 암호화/삭제:** SDK 통신도 포함해 전송 보안을 확인합니다. 앱 계정 삭제 절차가 Google의 광고 데이터까지 자동 삭제한다고 설명하지 않습니다. 공개 정책과 Google의 데이터/권리 행사 안내를 함께 확인합니다.
- **광고 포함:** AdMob 광고를 실제 표시할 수 있는 테스트/라이브 빌드는 Play의 광고 포함 응답을 검토합니다. 앱에 SDK가 있으나 `off`인 경우에도 v98와 동일하다고 자동 간주하지 말고 최종 AAB의 동작을 확인합니다.

## 새 CSV를 만들기 전

1. 소유자가 현재 Play Console에서 데이터 보안 CSV를 내보내 백업합니다. 이전에 업로드한 파일과 실제 저장/제출된 응답이 같은지 확인합니다.
2. 최종 광고 포함 AAB의 SDK 버전과 공식 데이터 공개 원문을 확보하고 위 항목의 수집·공유·목적·선택권을 확정합니다. 공식 원문 접근이 막힌 상태에서 추정만으로 추가 위치/오류 응답을 자동 생성하지 않습니다.
3. v98의 인증·구매 데이터 및 기존 SDK 유형을 보존하면서 필요한 추가 유형과 변경 목적을 반영합니다. 최신 Console 질문/응답 ID·행 수에 맞춰 **전체 응답 파일**을 만듭니다.
4. 가져오기 전후 응답을 화면에서 대조합니다. 기존 응답을 대체할 수 있으므로 부분 파일을 병합용으로 쓰지 않습니다. 소유자가 확인한 뒤 저장·제출하고 실제 출시 버전에 맞는지 마지막으로 확인합니다.

AdMob 계정/앱/공개 ID, UMP, `app-ads.txt` 및 실제 광고 전환 순서는 [AdMob 설정 안내](../ADMOB_SETUP.md)에 있습니다.
