## 공식 자료에서 확인한 내용

출처는 [Google Mobile Ads Android 데이터 공개](https://developers.google.com/admob/android/privacy/play-data-disclosure)입니다. 환경의 HTTP 접근 차단 후 소유자가 공식 페이지 화면을 제공했고 상위 작업 담당자가 직접 읽어 확인했습니다. 이번 CSV 확정 단계에서 네트워크 재요청이나 우회는 하지 않았습니다.

Legacy SDK는 다음을 **광고·분석·사기 방지를 위해 자동 수집하고 공유**한다고 명시합니다.

| 공식 데이터 범주 및 예시 | 반영한 Play 유형 |
| --- | --- |
| IP 주소, 이를 이용한 대략적 위치 추정 | 대략적인 위치 |
| 제품 상호작용: 앱 시작·탭·동영상 조회 | 앱 상호작용 |

공식 화면은 수집되는 모든 사용자 데이터를 전송 중 TLS로 암호화한다고 설명합니다. 기존 전송 암호화 응답을 유지했습니다.

## 최종 응답 요약

총 8유형을 수집하고 모두 임시 처리 아님으로 작성했습니다. 공유는 사용자 ID·대략적인 위치·앱 상호작용·진단·기기 또는 기타 ID의 5유형입니다. 이 5유형에는 광고·분석·사기 예방/보안 목적을 수집·공유 양쪽에 반영하고 기존 기능 목적은 유지했습니다. 이름·이메일·구매 내역은 기존 수집만·선택 응답과 목적을 보존했습니다. 개인 맞춤설정·개발자 커뮤니케이션 목적은 추가하지 않았습니다.

## 직접 근거와 구분한 판단

**사용자 ID:** 공식 자료가 기기 계정 관련 식별자를 조건부로 포함하므로, 기존 사용자 ID 유형에도 자동 SDK 처리를 합산하는 보수적 분류를 적용했습니다. 사용자 ID에 공유와 광고·분석·사기 예방 목적을 추가하고 유형 전체 선택권을 필수로 변경했습니다. 공식 화면이 Play 질문 ID를 직접 지정한 것은 아닙니다. 이 대응은 검토 판단이며 Firebase UID·이메일을 광고 extras로 전달한다거나 SOUL READER에서 Google 로그인을 필수로 요구한다는 뜻이 아닙니다.

**선택권과 임시 처리:** UMP/비개인 맞춤 설정이 모든 사용자·지역의 SDK 전체 수집 중지권을 의미하지 않으므로 SDK 관련 5유형은 필수로 작성했습니다. 이름·이메일·구매 내역은 선택으로 유지했습니다. 새 대략적 위치는 광고·분석·사기 방지 처리가 즉시 요청 처리 중 메모리에서만 끝난다는 근거가 없어 임시 처리 아님으로 작성했습니다. 이는 현재 구성을 반영한 판단입니다.

**진단 유형:** 화면의 실행 시간·중단율·에너지 사용 예시는 진단으로 대응했습니다. 원시 비정상 종료 로그가 명시되지 않아 `비정상 종료 로그`를 추가하지 않았고, 동일 예시를 이유로 `기타 앱 성능 데이터`를 중복 추가하지 않았습니다. 모든 상황에서 로그 처리가 없다는 단정은 아닙니다. SDK나 추가 중개 어댑터가 바뀌면 다시 검토합니다.

**코드와 버전:** Flutter `google_mobile_ads 9.2.0`의 기본 Android SDK는 Legacy GMA `25.5.0`, UMP `4.0.0`이며, 상위 작업에서 확인한 패키지/빌드 설정에 Next Gen 사용은 없습니다. 이 CSV 작업이 최종 AAB 의존성을 새로 빌드했다는 뜻은 아닙니다. 앱은 동의 준비 후 SDK 초기화·요청으로 진행하고 `AdRequest(nonPersonalizedAds: true)`를 사용합니다. 사진·얼굴 특징·풀이 본문·풀이 ID·Firebase UID·이메일·구매 토큰을 광고 extras로 넣지 않습니다. 앱의 직접 전달 여부와 SDK 자체 식별자 처리를 구분했습니다.

정밀 위치·사진·동영상·연락처·결제 수단 등 다른 유형은 이 광고 추가만으로 선택하지 않았습니다. 현재 783행 CSV에는 광고 포함 여부 질문이 없습니다. 실제 광고 기능에 맞는 광고 포함 응답은 Play의 별도 앱 콘텐츠 항목에서 확인합니다. [AdMob 설정 안내](../ADMOB_SETUP.md)도 참조하세요.
