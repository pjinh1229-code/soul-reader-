## 2. 앱 액세스 — 실제 동작에 맞춰 입력

무료 시작 화면과 기본 사진 풀이는 로그인 없이 이용합니다. 구매·구매 내역 확인·복원에는 **Google로 로그인**이 필요합니다. Firebase Authentication에 Google 계정을 연결하며 별도의 앱 비밀번호 입력 화면은 없습니다.

Console의 **앱 콘텐츠 → 앱 액세스 권한**에서는 유료·로그인 영역이 있으므로 전체가 제한 없이 공개되어 있다고 선택하지 않습니다. 아래 무료 동작 안내와 함께 제한 영역의 실제 심사 접근 방법을 작성합니다.

```text
무료 영역 확인: 앱을 실행하고 한국어를 선택한 뒤 ‘류에게 관상 보기’로 시작합니다. 사진 사용 안내에 동의하고 한 사람의 정면 사진을 촬영하거나 갤러리에서 선택합니다. 얼굴 분석과 무료 풀이를 완료합니다.

제한 영역: ‘이용권 구매’ 화면의 ‘Google로 로그인’으로 앱 계정을 연결합니다. 한 주제 이용권은 해당 사진의 한 주제를 확정하며, 합본은 해당 사진의 네 주제를 제공합니다. 같은 계정의 ‘구매 내역 복원’은 이 기기에 풀이 기록이 남아 있을 때 사용합니다.
```

**제한 영역 안내는 다음 준비가 끝난 뒤 추가합니다.** 이 저장소에는 심사 전용 무조건 해금·로그인 우회 기능이 없습니다.

- 소유자가 관리하는 심사용 Google 계정 등 Console에서 허용되는 접근 수단을 실제로 준비하고, 공개 제출 빌드에서 Google 로그인까지 확인합니다. 사용할 수 없는 비밀번호, 소유자 개인 계정 또는 추가 인증 없이는 접근할 수 없는 계정을 안내하지 않습니다.
- 무료 테스트 결제를 쓸 경우 실제 심사 계정에 필요한 Play 테스트 참여·라이선스 테스터 설정을 적용하고, **제출 빌드의 해당 계정에서 무료 테스트 결제와 네 주제 접근까지 확인**합니다. 일반 테스터 설정이 Google 심사자에게 자동 적용된다고 가정하지 않습니다.
- 위 방법으로 심사자가 무료로 전체 기능을 사용할 수 없다면 Console 안내에 맞는 별도 접근 방법을 먼저 마련합니다. 검증 전에는 ‘심사자는 무료’, ‘어떤 Google 계정도 전체 해금’, ‘로그인 불필요’라고 제출하지 않습니다.
- 비공개 계정 정보는 Console의 심사자 전용 칸에만 입력합니다. 접근 단계, 계정, 추가 인증 유무, 테스트 결제 경로와 검증 날짜를 적고 최종 제출 전 재확인합니다.

무료 영역 안내만으로 앱 액세스 등록이 완료된 것은 아닙니다.

## 3. 데이터 보안 — 코드 기반 초안, 최종 신고 전 검토

얼굴 사진을 서버에 올리지 않아도 로그인·구매 데이터는 기기 밖에서 처리됩니다. 앱 전체를 **‘데이터 수집 없음’으로 신고하지 않습니다.** 다음 표는 현재 코드가 확인해 주는 범위이며 최종 Console 응답은 SDK와 운영 설정까지 대조합니다.

추가 필드도 아래 기준으로 검토합니다.

- **수집/공유:** Firebase·Google Play·Cloudflare로 나가는 흐름과 수신자의 역할을 적습니다. Console의 서비스 제공업체 등 예외 정의를 검토한 뒤 공유 여부를 선택합니다. ‘판매하지 않음’만으로 ‘공유 없음’을 확정하지 않습니다.
- **선택/필수:** 로그인 없는 무료 기능과 로그인·결제가 필요한 유료 기능을 기준으로, Console의 데이터 유형별 정의에 맞춰 답합니다. 같은 유형을 SDK가 자동 수집하면 선택이라고 단정하지 않습니다.
- **일시적 처리:** 서버 구매 원장과 Firebase 계정은 요청 처리 직후 사라지는 데이터가 아닙니다. 모두 ‘일시적’으로 선택하지 않습니다.
- **전송 암호화:** 구매 서버는 HTTPS·인증 토큰을 사용합니다. ‘모든 사용자 데이터가 전송 중 암호화됨’ 응답은 포함 SDK와 운영 통신도 확인한 뒤 제출합니다.
- **삭제:** 공개 삭제 요청 URL과 앱 내 계정 삭제 진입점, 본인 확인·Firebase 계정·원장/기타 데이터 처리 절차를 실제로 확인합니다. 로그아웃·로컬 풀이 삭제·환불을 계정 삭제와 같은 동작으로 설명하지 않습니다.
- **보관:** 준비한 수동 삭제 절차는 Firebase 계정과 UID에 연결된 원장·암호화 구매 토큰 등을 제거하되, 거래 재사용 방지를 위해 구매 토큰 해시·취소/차단 시각을 서비스 운영 동안 남기는 구조입니다. 실제 삭제·예외가 공개 정책과 일치하는지 확인합니다. 근거 없이 ‘즉시 전부 삭제’, ‘법정 5년 보관’ 또는 자동 만료를 약속하지 않습니다.

## 4. Console에서 소유자가 마무리할 항목

아래는 소유자의 비공개 Console에서 확인·입력해야 합니다. 준비한 문서를 만들었다고 자동 제출되지는 않습니다.

- [ ] 계정·연락처·기기 인증, 결제 프로필·정산·필요한 판매/세금 정보를 확인합니다.
- [ ] 운영자 표시 `SOUL READER 운영자`를 반영하고 공개 개발자 이름을 대조합니다. 성인 만 18세 이상 초안을 실제 대상과 확인한 뒤 타겟 연령·판매 국가·한국 상품 가격을 설정합니다.
- [ ] 스토어 소개·지원 이메일·엔터테인먼트 카테고리·실제 화면 자산을 등록합니다. 최종 빌드에 광고가 없으면 광고 포함 여부는 ‘아니요’로 작성합니다.
- [ ] 공개 개인정보처리방침 URL과 계정 삭제 URL을 등록하고 앱에서도 필요한 진입이 되는지 확인합니다.
- [ ] 앱 액세스, 데이터 보안, 콘텐츠 등급, 타겟층·콘텐츠, 광고 및 그 밖의 필수 앱 콘텐츠 설문을 실제 기능에 맞춰 저장합니다. 관상 이야기를 의료·금융 서비스로 오인시킬 답변을 하지 않습니다.
- [ ] 개인 계정에 표시되는 출시 전 테스트/프로덕션 액세스 요건을 확인하고 이행합니다. 내부 테스트 완료만으로 닫힌 테스트나 프로덕션 액세스가 승인되지는 않습니다. 필요한 테스터 수·기간은 계정에 표시된 최신 기준을 사용합니다.
- [ ] 서명·패키지·현재 요구 target API/정책을 확인한 최종 AAB를 업로드합니다. **변경한 앱을 새로 빌드해 업로드할 때는 97 이상이며 기존 모든 코드보다 큰 값**을 사용하고 원래 업로드 키·음원 70개를 보존합니다. 변경 없는 기존 v96을 Console의 번들 목록에서 다른 트랙으로 승격하는 것은 새 파일 중복 업로드와 구분합니다.
- [ ] 제출 AAB를 Play에서 설치해 무료 풀이·로그인·가격·한 주제/합본·복원·환불과 개인정보/삭제 진입을 확인합니다. 내부 v96 시험 이후 변경된 기능도 확인합니다.
- [ ] 심사자가 추가 구매 비용 없이 제한 영역을 확인하는 경로를 실제 설정·검증하고 Console 심사 지침에 기록합니다.
- [ ] 정책/배포 오류와 필수 누락을 해결한 뒤 프로덕션 심사에 제출합니다. 승인 결과, 공개 국가와 실제 스토어 공개를 별도로 확인합니다.
